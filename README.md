# CashBrain — цифровой помощник предпринимателя в MAX

Чат-бот в мессенджере MAX, который помогает индивидуальным предпринимателям
и малому бизнесу решать две задачи на старте:

1. 🏛 **Найти меры государственной поддержки** — субсидии, гранты, льготные
   кредиты — под профиль конкретного бизнеса.
2. 📢 **Найти блогеров для рекламы** — по тематике, размеру аудитории
   и активности, с оценкой эффективности размещения.

Бот связывает обе задачи в единый сценарий: предприниматель получает
финансирование → распределяет бюджет → находит канал продвижения.

---

## 🎯 Целевая аудитория

Индивидуальные предприниматели и малые компании на этапе запуска или
масштабирования, которым нужно:
- разобраться в доступных мерах господдержки без изучения десятков сайтов;
- понять, сколько денег можно привлечь и как их распределить;
- найти релевантные каналы для первых рекламных кампаний.

Приоритетный сегмент MVP: **ИП в сфере услуг и торговли** (кофейни,
производство, IT-услуги), работающие в регионах РФ.

### Пользовательский сценарий

#### Шаг 1: Профиль ИП

Бот задаёт **4 вопроса** последовательно:

| Вопрос | Пример ответа | Что сохраняется |
|---|---|---|
| В какой сфере вы работаете? | «кофейня» | `industry` |
| В каком регионе вы ведёте деятельность? | «Нижегородская область» | `region` |
| Какой у вас начальный капитал? | «500000» | `initial_capital` |
| Какую ежемесячную выручку вы хотите получать? | «300000» | `target_revenue` |

**Важно:** вопрос о выручке сформулирован как **цель** — это подходит и для действующего ИП (он указывает текущую выручку), и для начинающего (он указывает желаемую).

#### Шаг 2: Подбор госпрограмм

Бот вызывает `core/matcher.py`, который фильтрует программы по:
- **Региону** — федеральные (`"все"`) + региональные.
- **Отрасли** — совпадение с отраслью ИП.
- **Максимальной выручке** — если у программы есть лимит.

Результат: список программ с суммами, ставками и ссылками. Бот **разделяет** их на федеральные и региональные, а если региональных нет — **честно предупреждает** об этом.

#### Шаг 3: Расчёт дохода (без маркетинга)

Бот вызывает `core/calculator.py` и считает **3 сценария**:

| Сценарий | Рост выручки | Расходы |
|---|---|---|
| 🟢 Оптимистичный | +20% к цели | 55% от выручки |
| 🟡 Реалистичный | +10% к цели | 60% от выручки |
| 🔴 Пессимистичный | 0% | 70% от выручки |

Для каждого сценария считаются:
- Прогноз выручки
- Чистая прибыль
- ROI
- Срок окупаемости

Также бот строит **рейтинг программ по ROI** — чтобы пользователь видел, какая программа выгоднее.

#### Шаг 4: Распределение бюджета

Бот показывает **3 сценария распределения** привлечённого финансирования:

| Сценарий | Оборудование | Маркетинг | Аренда | Резерв |
|---|---|---|---|---|
| 🟢 Осторожный | 50% | 15% | 20% | 15% |
| 🟡 Сбалансированный | 40% | 30% | 20% | 10% |
| 🔴 Агрессивный | 30% | 45% | 15% | 10% |

Пользователь выбирает сценарий. Бот сохраняет `marketing_budget` — он понадобится на следующем шаге.

#### Шаг 5: Подбор блогеров (автоматически)

Бот **автоматически** вызывает `core/marketing.py` и подбирает блогеров:
- Фильтрует по темам (сопоставляет отрасль ИП с темами каналов).
- Сортирует по **score** (ER + охват).
- Показывает **ТОП-5** каналов с метриками:
  - Подписчики, посты, средние просмотры, реакции
  - **ER** (Engagement Rate)
  - **Охват** (Reach)
  - **Оценка 0–100**

**Важно:** блогеры подбираются **под маркетинговый бюджет**, выбранный на шаге 4. Пользователю не нужно вводить параметры вручную.

#### Шаг 6: Финальный прогноз дохода (с учётом PR)

Бот **пересчитывает** 3 сценария дохода с учётом `marketing_budget`:

- Прогноз выручки = цель + прирост от маркетинга.
- Прирост зависит от сценария: ×2 / ×3 / ×4.
- ROI и окупаемость пересчитываются.

Пользователь получает **итоговый отчёт** — сколько заработает с учётом рекламы у блогеров.

### Что получает пользователь

1. **Список госпрограмм** — какие доступны именно ему.
2. **Прогноз дохода** — 3 сценария с ROI и окупаемостью.
3. **План распределения бюджета** — куда вложить средства.
4. **Подборку блогеров** — под маркетинговый бюджет.
5. **Финальный прогноз прибыли** — с учётом PR.

### Чем это отличается от «просто навигатора»

Обычный навигатор показывает **список программ**. CashBrain показывает **полный путь**:

## 🧠 Как устроен диалог: FSM

FSM (Finite State Machine) — механизм, который позволяет боту **помнить**,
на каком шаге диалога находится пользователь. Без FSM бот не смог бы
отличить ответ на вопрос «В каком вы регионе?» от ответа на вопрос
«Какая у вас выручка?».

В проекте используются две группы состояний:

```python
# bot/handlers/profile.py
class ProfileForm(State):
    waiting_for_industry = State()
    waiting_for_region = State()
    waiting_for_capital = State()
    waiting_for_target_revenue = State()

# bot/handlers/bloggers.py
class BloggersForm(State):
    waiting_for_topic = State()
    waiting_for_min_subs = State()
    waiting_for_max_subs = State()
    waiting_for_ads_filter = State()
```

Все текстовые сообщения проходят через **единый роутер** (`bot/handlers/router.py`),
который смотрит на текущий state и делегирует обработку в нужную функцию.

## 🚀 Запуск

### Вариант 1. Локально (для разработки)

Требуется Python 3.11+.

```bash
# 1. Создать и активировать виртуальное окружение
python -m venv venv
venv\Scripts\activate           # Windows
# source venv/bin/activate      # macOS / Linux

# 2. Установить зависимости
pip install -r requirements.txt

# 3. Создать .env по образцу .env.example
copy .env.example .env          # Windows
# cp .env.example .env          # macOS / Linux
# Вписать в .env токен бота (MAX_BOT_TOKEN=...)

# 4. Запустить симулятор (без MAX, работает без токена)
python simulate.py

# 5. Или запустить реального бота в MAX
python -m bot.main
```

### Вариант 2. Через Docker

```bash
# 1. Создать .env с токеном
copy .env.example .env
# Вписать MAX_BOT_TOKEN

# 2. Запустить
docker compose up

# 3. Остановить
docker compose down
```

Все зависимости, БД и запуск бота — внутри контейнера. Токен подхватывается
из `.env`.

## 📊 Источники данных

### Программы поддержки (`data/sources/programs.json`)

15 программ, собранных **вручную** из открытых источников:
- МСП.РФ
- Минэкономразвития РФ
- Региональные центры «Мой бизнес»

Данные актуальны на сентябрь 2026 года.

### Блогеры (`data/sources/bloggers.json`)

39 каналов в MAX, собранных **вручную** через [maxstat.ru](https://maxstat.ru/):
- название, ссылка, тематика (2–3 тега на канал);
- подписчики, число публикаций, средние просмотры и реакции;
- признак «есть реклама в канале» — проставлен вручную.

**Автоматическая интеграция с внешними API в MVP отсутствует** —
это сознательное решение, соответствующее правилам хакатона
(запрет на частные API и токены в репозитории).

В проде планируется автоматическое обновление метрик через API
MaxStat (коммерческая подписка).

## 📐 Как считается оценка блогера

Метрики считаются в `core/marketing.py`:

**ER (Engagement Rate):**
```
ER = avg_likes / subscribers × 100%
```

**Охват (Reach):**
```
Reach = avg_views / subscribers × 100%
```

**Сводная оценка (0–100):**
```
score = min(ER/10, 1) × 60 + min(Reach/100, 1) × 40
```

Наличие рекламы (`has_ads`) **не учитывается в score** — это фильтр,
а не критерий качества канала.

## ⚠️ Известные ограничения MVP

1. **Данные о блогерах статичны** — база в `bloggers.json`, обновляется вручную
   через `scripts/excel_to_json.py`.
2. **Нет автодетекта рекламы** — признак «есть реклама» проставлен вручную.
   В проде — поиск по маркерам `#реклама` / `erid`.
3. **Расценки блогеров не собираются** — в MAX блогеры не публикуют
   прайсы открыто.
4. **Комментарии не собираются** — в MAX их сложно получить через публичный API.
5. **Регион в программах — по подстроке**, не по ФИАС-коду.
6. **SQLite** — для MVP, в проде потребуется PostgreSQL.
